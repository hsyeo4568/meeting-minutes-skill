# Marker and correction policy

이 문서는 `(*...)`가 원문에 있거나 자동 마킹을 요청했을 때 적용한다. 마킹은 원문을 해석하는 부가 표식일 뿐, 숫자·표현·발화 내용을 고치는 수단이 아니다.

## 먼저 보호하고, 위반 시 중단

1. 모든 `(*...)` span을 어떤 분류·교정보다 먼저 mask한다. 괄호 깊이가 0이 되는 닫는 괄호까지를 하나의 span으로 본다.
2. 200자 또는 빈 줄 전까지 닫히지 않거나 span 안에 다시 `(*`가 나오면 marker violation이다. 해당 발언의 나머지는 동결하고 **fail-closed**로 적용을 중단한다.
3. `(*)` 내부에는 교정·물음표 복원·glossary 누적·새 마커 삽입을 하지 않는다. 원문 `(*)`가 이미 있는 주제 군에는 새 마커를 추가하지 않는다.

## 괄호 형태 분류

- `wrong(right)`는 right가 glossary 정식어이거나 음운·문맥 근거가 충분할 때만 right로 바꾼다. 두 형태가 모두 유효한 일반어이면 **Tier-C** 보류다.
- `(오타: right)`는 명시 교정으로 처리할 수 있으며, `phrase(삭제)`는 그 phrase만 제거한다.
- 문장 끝 `(?)`, 지문·강조용 괄호는 보존한다.
- 화자 라벨, 수치·단위, 검증되지 않은 인명은 Tier-C로 유지한다.

## 자동 마킹

명확한 신호에 한해 발화 블록의 마지막 줄 끝에 공백 뒤로 추가한다. 새 줄을 만들지 않으며, 한 번의 append pass로 적용한다.

| 신호 | 형식 |
|---|---|
| 데이터 의미·함의 | `(*인사이트_…)` |
| 탐색적 아이디어 | `(*brainstorming_…)` |
| 명시 작업 약속 | `(*to-do_… : 담당)` |
| 확인·자료 요청 | `(*확인 필요_… : 주체)` |
| 합의된 결정·방향 | `(*결정_…)`, `(*방향성_…)` |
| 토론 정리 | `(*정리)` |

기존 마커와 요청 마커를 합친 총량은 **max(15, lines // 16)**을 넘지 않는다. 숫자 나열·계산 중 발화·인사·짧은 동의·단순 사실·슬라이드 문구 낭독에는 마킹하지 않는다. 애매하면 삽입하지 말고 marking candidate로 보고한다.

## 적용 후 경계

마커는 발화 끝에만 붙이고 line-count parity를 유지한다. 적용/후보 교정/보류/삽입 마커 목록을 서로 분리해 반환하며, 위반·수치·화자 문제는 교정을 계속 진행하지 않는다.
